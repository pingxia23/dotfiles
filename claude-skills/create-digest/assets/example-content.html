Durable timers beat in-process timers for agent follow-ups

Jane Doe · #example-channel · 12 replies

Scheduled agent follow-ups kept only in memory vanish on every deploy; move them to a durable scheduler.

Why this matters

Any agent that "checks back later" depends on its scheduler surviving restarts. This thread shows a silent failure and the fix.

Main takeaway

A stored row is not a scheduled job: the follow-up must be re-armed on startup or owned by a durable scheduler. The fix is staged, not yet in production.

2. What the fix changes

Before

Timer lives in one server process.

After

A durable scheduler owns the timer and survives restarts.

  1. Write the desired scheduleThe agent writes a row, as before.
  2. Sync to the schedulerA sync job turns rows into durable schedules.
  3. DeliverThe scheduler fires through a queue that retries.
